# Beauty Salon OS V5 — 门店工作台 / 前端现代化升级

基于 V4 源码直接修改，未修改 PostgreSQL 结构，**不新增数据库迁移**，不更换预约及收银 API。

## 实际修改的页面

| 页面/模块 | 变化 | 实际业务价值 |
| --- | --- | --- |
| 店长工作台 `apps/admin-web/src/App.tsx` | 品牌侧栏、分组式图标导航、桌面顶栏、移动端快捷底栏、中日双语切换、角色可见性 | 高频操作更容易找到；员工不误入店长管理页 |
| 排单 `pages/Calendar.tsx` | 新营业概览、检索筛选、接待/服务清单、改进技师列与预约卡片、加载失败提示 | 前台先看到当天待处理顾客，再处理预约；减少无效点击 |
| 拖拽改期 `pages/Calendar.tsx` | **新增原日期/新日期及技师确认框**，确认后才请求旧的 `/reschedule` API | 触屏/鼠标误拖不会悄悄更改真实订单；服务器仍复核冲突 |
| 预约详情 `pages/Calendar.tsx` | 一键拨号、复制预约摘要（需浏览器剪贴板权限） | 前台电话沟通更快；不假装已经发 LINE |
| 顾客预约 `apps/customer-web` | 新品牌设计、四步进度、项目卡片、响应式布局及 JST 提示 | 日本顾客和在日华人都更容易完成自助预约 |
| 日期选择 `DateTimePicker.tsx` | **切换日期清空旧时段/旧选中状态**，加载失败可重试 | 避免切换日期后误提交前一日期的时段 |
| 客户管理 `pages/Customers.tsx` | 手机卡片/桌面表格、错误状态、CSV 导出 | 不用在手机上横向挤四列；支持导出当前可见数据 |
| 经营报表 `pages/Reports.tsx` | 更新视觉、日期范围校验、错误提示 | 网络失败不会误显示为零经营额 |
| 收银 `pages/Payments.tsx` | 净收款显示、日期范围校验、数据导出、错误提示 | 可进行基础流水核对；出错不伪装成零收入 |
| 登录 `pages/Login.tsx` | 原创双栏登录页、密码显示开关、中日双语 | 提升正式门店员工操作体验 |
| 通用弹窗 `lib/ui.tsx` | 现代圆角、遮罩、Esc 关闭及 dialog 语义 | 键盘操作更顺畅 |
| CSV `lib/export-csv.ts` | 带 UTF-8 BOM、CRLF、CSV 字段转义、公式注入处理 | 日本 Excel 可读；降低 CSV 注入风险 |

## 业务正确性修复

- 客户、报表、收银的前端请求加入递增序号：晚返回的**旧请求不会覆盖新查询结果**。
- 原有日历后端硬约束/资源锁保持不变；前端不会自行绕过冲突检测。
- 拖拽改期需**用户二次确认**；取消只清除候选修改，不会触发后端改期请求。
- 导出按钮只在列表正常加载且非空时可点；导出的 CSV 是**当前加载结果**，可能不是全库记录。
- 每个涉及数据失败的页面均给出失败提示和重试，区别于真实的空数据。
- **没有声称**实现真实 LINE 发送、支付平台接入、照片存储、自动候补功能，这些仍需后续开发。

## 部署与兼容

沿用 V4 的 `docs/DEPLOY_V4.md`，无需额外数据库迁移。升级前仍建议备份数据库、客户资料和配置文件。新前端发布需重新构建管理端与顾客端镜像；旧版登录态仍服从 V4 HttpOnly Cookie 机制。

```bash
npm install
npm run build:web
npm test
cd infra && docker compose up -d --build
```

**本工作环境因 registry.npmjs.org 的 DNS 错误（EAI_AGAIN）无法获得 npm 依赖，故没有完整 Vite 打包、浏览器联调或 PostgreSQL 集成测试成功记录。** 部署到正式店铺前必须补跑上述命令及 `docs/QA_V5.md` 的验收流程。
