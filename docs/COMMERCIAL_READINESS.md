# Beauty Salon OS — 商用级差距审计（V5.1）

## 这次确认并修改的 3 个问题

1. 退款接口审计记录错误引用事务内局部变量 `orig`，退款已写入时接口可能报 500。已改用路径参数中的原单 ID，并增强退款回归断言。
2. `mock` 通知此前被记录为 `sent`，造成虚假送达状态。现改成 `skipped`，无真实送达时间，说明记录在 `lastError`。
3. LINE 通知模板各事件标题原先为空。已填充日中双语预约确认、取消、改期与到店提醒标题。

## 仍未达到商用级的关键事项

- 端到端验收：完整依赖安装、生产构建、真实 PostgreSQL、API 全量集成、浏览器和移动端测试。
- 顾客身份与防滥用：手机/邮件验证码，公开预约滥用监测，预约请求幂等处理。
- 收银闭环：日结、班次交接、支付渠道对账、税率/消费税、收据、折扣、预付款和退款审批。
- 护理电子档案：作品照片与附件管理、告知同意、敏感信息访问记录及保留策略。
- 通知闭环：生产 LINE 凭据、顾客绑定、送达失败处理、其它渠道提供商接入。
- 现场调度：候补补位、多个技师/资源参与同一订单、节假日营业例外、服务延时、实时消息。
- 服务运营：异常报警、定期可恢复备份、可验证的回滚方案、员工培训与客服处理规范。

## 上线原则

V5.1 是关键修复补丁，不是完成的商用版。不要在未经数据库/浏览器/通知验证的情况下对公众正式开放。优先达到【单店试营业】的验收条件，再推进对外销售的 SaaS 多租户能力。
