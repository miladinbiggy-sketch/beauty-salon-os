# V2 历史安全审计（已被 V3 部分修复）

> 本文是 V2 快照，不代表 V3 的实时状态。Cookie 与 Redis 限流已在 V3 修改，详情见 [CHANGELOG_V3.md](CHANGELOG_V3.md) 与 [DEPLOY_V3.md](DEPLOY_V3.md)。其余遗留风险仍需处理。

**已落地：**生产 JWT_SECRET 至少 32 位且不能是默认开发密钥；production CORS 禁止 `*`；默认禁止演示种子，登录页不再一键填 demo 密码；新店主通过单独初始化脚本创建；新增护理档案需门店归属及技师关系授权，读取写入都有审计摘要；附加项目和员工技能增加跨门店验证。

**尚需处理（不应忽视）：**

- 目前管理端的 JWT 仍存 `localStorage`，受 XSS 风险影响。正式商用应迁移到 HttpOnly/Secure/SameSite 会话 Cookie，并加入 CSRF 防护、短效 access token 和服务端注销/撤销。
- 登录和公开预约限流仍是单进程内存 `Map`，且原 `clientIp` 信任 `X-Forwarded-For`。上线前应调整为 Redis 共享限流，并限制 API 只能被可信 Caddy 反代访问、可信代理重写来源头。
- 护理档案文字记录未加密到字段级，也没有完整的信息保存、删除及更正规则；**不要收集医疗诊断或不必要的敏感健康信息**。根据日本个人信息保护要求，发布利用目的、访问政策、保留周期及事件处置流程。
- 本轮没有集成照片上传与私人对象存储；不得在公开静态目录保存客户照片或未经授权的公开 URL。
- 在上线前进行真正 Postgres 集成测试、并发验证和安全渗透测试，给备份定期演练与监控告警。
- 演示资料可能含虚构姓名、电话等，应与正式门店数据隔离。
